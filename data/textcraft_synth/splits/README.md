# TextCraft-Synth official split

Frozen benchmark definitions for the `textcraft_synth` environment. Source:
[`platoon-textcraft`](https://pypi.org/project/platoon-textcraft/) 0.4.0
(MIT), `textcraft_synth_train.jsonl` (2,522 tasks, SHA-256
`685823fbca90aa89e061e61fef58d0122def4221eed14cf2c8c730341363a00f`).

The split follows the recommended profile:

| split | recipe depth (`misc.max_depth`) | tasks | selection |
|---|---|---|---|
| `train` | 2-4 | 200 | first slice of the depth-2/3/4 pool |
| `id` | 2-4 | 150 | next slice of the same pool (new task instances) |
| `ood` | 5-6 | 150 | depth-5/6 pool (deeper trees, unseen goals) |

Every depth bucket is sorted by its numeric task id and the buckets are
round-robin interleaved (2,3,4,2,3,4,...), so a partial prefix still covers
the whole depth range. The three splits are disjoint task instances. Per
depth: train 67/67/66, ID 50/50/50, OOD 75/75.

Each record carries `item_id`, `split`, `task` (`craft`), `goal`,
`target_items`, `initial_inventory`, `max_steps`, `max_depth`,
`difficulty`, and `source_id` (the published task id). Episode ids are
positional over the record order -- do not reorder a manifest when resuming
a batch.

`../recipes.json` is the frozen synthetic world (`textcraft-recipes/1`
format): 1,452 items, 1,402 recipes, generated by the vendored
`synth_recipe_generator` (seed 42, 25 items per domain/tier).

Rebuild / validate:

```bash
/opt/python/bin/python scripts/make_textcraft_synth_split.py --download
/opt/python/bin/python scripts/make_textcraft_synth_split.py --check
```
